# 拾光相册

一个使用 HTML、CSS 和 JavaScript 的深色个人相册。解压后双击 `index.html` 就能浏览示例相册。照片按拍摄日期从新到旧排列。搜索框匹配标题或标签，分类和搜索可以同时使用。灯箱在当前筛选结果中循环切换，支持左右方向键和 Esc。

## 浏览照片

- 用分类按钮、年份和搜索组合筛选照片。搜索支持空格分隔的多个关键词，照片需要同时匹配这些词。点击「清除筛选」恢复全部照片。
- 排序可以选择拍摄日期从新到旧、从旧到新，或按中文标题升序。大图中的切换顺序跟随当前筛选和排序结果。
- 大图底部显示标签。点击标签会返回照片墙并搜索这个标签。手机上可在大图区域单指左右滑动切换，双指缩放使用浏览器原生手势。
- 大图加载中会显示提示。图片缺失时，页面给出检查路径的提示和重新加载按钮。
- 点击「拾光时间线」按年份和月份回看照片，每年显示总数、照片最多的月份和里程碑数量。日期与当前分类、年份和搜索筛选一致。照片详情可更改分类或标记里程碑，修改会保存在本机浏览器。

## 批量导入

点击「批量添加照片」可一次选择多张，点击「导入照片文件夹」可选择文件夹，也可以将照片拖进页面的导入区域。浏览器使用内置解析器在本机读取 JPEG 的 EXIF 拍摄日期和 GPS；其他格式或读不到时使用文件修改日期。导入结束会分别显示拍摄时间和文件时间的数量。文件名含「截图」或 screenshot，以及宽高比达到 3:1 的图片归为「截图」；其余带 GPS 信息的照片归为「旅行」候选，其他照片归为「生活」。照片在时间线上按拍摄年月归档，详情中的分类可以修改。

导入的原图与照片信息写入当前浏览器的 IndexedDB，刷新后恢复。更换浏览器、网站地址或设备时，需要导出再导入 ZIP。浏览器清理站点数据、隐私模式结束或存储空间不足可能导致数据丢失，请定期导出备份。EXIF 库通过 jsDelivr CDN 加载；加载失败时批量导入会提示并停止，保留已有相册。

## 通过网页添加照片

1. 点「添加照片」，选择本机图片，填写标题、分类、拍摄日期和标签。日期按实际拍摄时间填写，标签用逗号隔开。
2. 点「加入当前相册」，照片会出现在当前页面。同名文件会生成不同的保存路径。
3. 点「导出私人存档」，浏览器会在本机生成 ZIP，包含当前清单中的私人原图和 `photos/private/photos.json`。请确认下载完成。
4. 以后重新打开相册，点「导入私人 ZIP」选择本相册导出的存档，即可在本机恢复照片与清单。导入支持本相册生成的无压缩、无密码 ZIP，导入时会检查 CRC、路径、文件类型和清单引用。校验失败时会保留当前相册。
5. 也可以手动把 ZIP 内的 `photos` 文件夹合并到相册根目录，再读取私人清单和选择照片文件夹。

手动添加、批量导入和 ZIP 导入的私人照片会写入浏览器 IndexedDB。导出时需要已选齐当前清单里的私人照片，可以根据页面上的匹配数量检查。生成存档失败时可以重新导出，当前预览仍可继续使用。

存档采用普通 ZIP 格式，包含原图及图片里原有的 EXIF 信息，请保存在自己的私人目录。网站通过浏览器下载保存存档，原来的照片文件由用户自行管理。

## 通过文件夹和清单添加照片

1. 在项目里新建 `photos/private/`，再按分类建子文件夹。例如把照片放在 `photos/private/旅行/青岛.jpg`。
2. 把根目录的 `photos.json` 复制到 `photos/private/photos.json`。用文本编辑器打开副本，删掉示例记录，按下面的格式填写自己的记录。
3. 双击根目录的 `index.html`。点右上角「读取照片清单」，选择 `photos/private/photos.json`。
4. 点「选择 photos 文件夹」，选择项目中的 `photos` 文件夹。浏览器会要求确认所选目录，确认后即可在本机查看自己的照片。页面会显示匹配到的私人照片数量。

本地 HTTP 预览使用同样的步骤。私人照片通过所选文件的临时 Blob 地址显示，清单里的 `photos/private/` 路径只用于匹配用户选中的文件。刷新或重新打开页面后，需要重新选择清单和文件夹。Chrome 和 Edge 可使用文件夹选择功能，其他浏览器以是否支持该功能为准。

```json
[
  {"file":"photos/private/旅行/青岛.jpg","title":"海边散步","category":"旅行","tags":["海边","周末"],"date":"2026-10-05"}
]
```

每新增一张照片，在数组里加一条记录，记录之间用逗号隔开。路径始终相对于 `index.html`，请使用正斜杠 `/`，并保持文件名和扩展名的大小写一致。日期使用 `YYYY-MM-DD`，没有标签时填写 `[]`。修改 `category` 就能添加或改名分类。要更新当前页面，再选一次修改后的清单。

直接双击时，浏览器通常会限制网页自动读取同目录的 JSON，因此首页先展示内置示例，使用文件选择器加载自己的清单。通过 GitHub Pages 等静态站点访问时，页面自动读取根目录的 `photos.json`。

## 隐私和提交规则

- 私人照片需要用户主动选择。照片写入本机 IndexedDB，文件夹读取的照片保存在当前页面内存中。「清除私人预览」释放临时地址并恢复示例，刷新后已保存到 IndexedDB 的照片会重新显示。
- 页面仍通过 CDN 加载 exifr，但批量导入不依赖它，照片解析、处理与存储在本机进行。CSP 限制网络连接和图片来源，标题、分类和标签用文本节点渲染。默认清单只从同源读取，使用无凭据、无缓存和禁止重定向的请求。私人照片使用 Blob 地址。
- 本次对话中的本地预览仅监听本机回环地址，拒绝 HTTP 直接访问私人目录和目录列表。自己使用其他静态服务器时，请在服务器配置中拒绝 `photos/private/` 的访问，或把私人文件移到网站发布目录之外。前端代码无法替托管服务器保护已发布的原图。
- 源码可被修改，页面保护规则也可被一起移除。具有本机文件访问权限的程序、浏览器扩展、网站管理员或已获准查看照片的人仍可能取得照片。此版本提供本地读取与外站请求限制，不包含登录认证或照片加密。

- `.gitignore` 默认排除 `photos/` 下的内容，只放行 `photos/生活/sample.svg`、`photos/旅行/sample.svg`、`photos/风景/sample.svg` 三张示例矢量图，同时排除 ZIP 存档。示例标题、标签和日期均为虚构占位信息。请给自己的照片使用新文件名，并把私人清单放在 `photos/private/`。直接覆盖已放行的示例文件，或把私人记录写入根目录的 `photos.json`，会让它们进入可提交范围。
- 提交前用 `git status --short` 检查待提交文件。已经被 Git 跟踪的文件和历史提交仍会保留，即使后来加了忽略规则。用 GitHub 网页手动上传时，请只选择准备公开的文件。
- GitHub Pages 上的相册应按公开内容处理。访客可以访问部署后的图片和根目录的 `photos.json`，包括其中的标题、日期和标签。只发布愿意公开的资料。

## 部署到 GitHub Pages

1. 新建 GitHub 仓库，把项目文件提交到 `main` 分支的根目录。保留 `.gitignore` 和 `.nojekyll`，也保留 `photos/` 的目录结构。发布示例相册时，保留根目录的示例清单。
2. 在仓库打开 **Settings → Pages**，在 **Source** 里选择 **Deploy from a branch**。分支选 `main`，目录选 `/(root)`，然后保存。
3. 部署成功后，在 **Settings → Pages** 点 **Visit site**。项目网址通常为 `https://用户名.github.io/仓库名/`。

本项目发布仓库为 [Wei798-rgh/photo-album](https://github.com/Wei798-rgh/photo-album)，发布分支为 `main`，目录为 `/(root)`，站点地址为 [拾光相册](https://wei798-rgh.github.io/photo-album/)。

如果要发布自己愿意公开的照片，把公开副本放入 `photos/分类名/`，在根目录的 `photos.json` 更新对应记录，并在 `.gitignore` 逐个放行这些路径。若是新分类，先放行分类目录，再放行单张图片。例如：

```gitignore
!/photos/美食/
!/photos/美食/面包.jpg
```
